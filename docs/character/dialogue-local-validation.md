# Closure 新角色卡与多轮会话：本地验证

本阶段把[角色卡](closure-role-card.zh-CN.txt)接入实际聊天请求，并让应用保存近期完整问答。用户要求先在本地试用，因此本次不推送、不创建 PR、不运行远端 CI、不合并；工程检查和本地安装结果另存于本次工作副本的 `.ai-workflow/dialogue-local/`。

## 已接入的行为

人设与输出协议使用独立资源。人设不附固定示范回答；显示文本、简短朗读文本和整条回复的情绪标签仍保留。模型参数适配沿用运行副本的实现，未切换模型或语音适配器。

请求最多携带最近 12 轮完整问答，历史部分另有 24,000 个 Unicode 码点预算。预算不足时从最早轮次开始省略，保留连续的完整问答，不截出半轮，历史助手只回放可见正文一次，不发送朗读摘要和情绪标签作为历史示范。这是字符预算，不声称等同于精确 token 数。单轮超过整个历史预算时，该轮仍可显示，但不会进入后续请求；界面恢复最多保留 100 轮已完成对话。

会话由应用持有。关窗、重新打开或重建聊天窗口后，当前进程中的完整问答仍在。重启应用会清空这些内容；本阶段没有 SQLite、滚动摘要或长期偏好库。模型请求明确说明当前可用能力，不能把一次聊天中的记住理解成永久保存。

连续发送的消息按顺序处理，后一轮在前一轮提交后组装上下文。失败、停止、过期回调或不完整协议输出不会成为成功历史，也不会触发对应朗读。完整协议按三个字符串字段校验；为兼容已有输出，闭合的 JSON 代码围栏可被去除，随后仍须通过完整字段、转义、长度和情绪标签检查。

“停止”会取消当前及排队的回复并停止朗读。“新对话”还会清空本次会话。聊天开场只用于界面，不进入用户事实或模型历史。情绪解析保留模型声明的主意图，带问号的调侃不会因词语混合被强制改成中性；原有朗读清洗和真实疑问的修正仍在。

## 本地试用顺序

完成本地安装后，从平时的“启动可露.command”启动，双击人物打开通讯窗口。以下输入为独立合成示例，用来观察行为，不作为提示词中的标准回答。

1. 输入“叫我小岚，技术解释尽量用中文”，下一轮问“刚才让我怎么称呼来着”。观察是否承接前文，以及是否夸大成永久保存。
2. 分享一件已完成的小事，再描述一个具体故障。观察是否能区分接话与排查，回复长度是否合适，是否反复使用同一句开场或结尾。
3. 关闭聊天窗口，重新打开，再继续上一话题。观察显示记录与实际回复是否都能承接。
4. 请求较长说明，在回复期间点“停止”，然后开始新话题。观察停止后是否还冒出旧回复或旧语音；连续发送两条消息时，第二条应接上第一轮的完整结果。
5. 点“新对话”，再询问先前约定。新请求不应继续携带已清空的历史。重启应用后也应从空会话开始。
6. 让它整理一条包含日期、数字或代码的消息。分别检查显示是否完整、朗读是否适合听、关键数字是否一致。

这些人工试用会使用你现有的模型服务。本次代理工程验证使用假模型、本机模拟接口和静音语音替身，没有进行云端模型效果评测。角色表现与听感仍待用户本地体验，不能从单元测试通过推断。

## 检查与回退

常规离线测试和打包沿用项目命令：

```sh
./mvnw -B -Djava.awt.headless=true test
./mvnw -B -DskipTests package
python3 scripts/verify_startup.py
```

原生聊天检查需桌面环境，使用合成后端和静音语音替身，不读取实际 AI/TTS 配置：

```sh
./mvnw -B -Djava.awt.headless=false -Dclosure.nativeChatTest=true -Dtest=ChatWindowLifecycleTest test
```

本次本地安装按精确文件清单备份，先核对原文件哈希，再替换并在实际运行目录重新测试、打包与验证启动。其他定制源码和私有设置保持原状。需要回退时按安装清单恢复对应备份，移除仅由此次新增的文件，重新构建并启动；不整体覆盖原项目。
