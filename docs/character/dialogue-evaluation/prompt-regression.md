# 文本提示词体验回归

2026 年 11 月 26 日以主分支提交 `48686b5a98dc519f6b20480797dc0d2f20d0432d` 为基线。角色卡聚焦可露希尔的身份和相处方式。文本提示词让日常分享先得到贴题的反应，技术问题按用户要求展开，并用前文最新的确认信息接话。流式协议优先输出 `displayText`，随后给出朗读文本和整句情绪标签。 [角色卡](../closure-role-card.zh-CN.txt) · [文本提示词](../../../src/main/resources/prompts/closure-system-prompt.txt)

## 本机对照

用同一个本机 Ollama 模型 `qwen3.5:4b-q4_K_M` 生成旧、新两组回复。两组都关闭思考模式，采样温度为 `0.8`，种子为 `20261126`，上下文上限为 `4096`，生成上限为 `768`。每例重建会话，用合成时钟和同一份历史夹具。多轮场景逐次发送用户输入，历史只接入上一轮有效的 `displayText`。评审使用用例的要求检查回复，发送给模型的请求只包含生成所需的信息。 [案例集](cases.v1.json)

初期轮次对照了 11 个场景，发现追加角色剧情、随意推断故障和压缩复杂技术回答都会妨碍对话。发布候选复测 A05、B04、C02、D02、D05、F04、G02，D05 取连续的前六轮。每版的原始回复、请求时延、参数和提示词校验值存于本次工程记录的 `experience/prompt-ab-release/`。

| 场景 | 发布候选观察 |
| --- | --- |
| A05 一句话回应 | 正文收在一句，后半句仍追加了用户没要求的叮嘱。 |
| B04 离线存档 | 按要求讨论了消息结构、写入时机和重启恢复。完整提交与恢复之间的一致性仍需更严谨的说明。 |
| C02 称呼和偏好 | 正文和朗读用了“小岚”，回复仍延伸到收费话题。 |
| D02 多轮更正 | 采用了更正后的 11 月 28 日。给定 11 月 23 日，正确间隔为五天，本次回复算成了三天。 |

这些观察对应本机模型的一次采样。完整的 40 例评测和日常模型体验仍待后续验证。

## 桌面回归

CLI 使用 JDK 21。聊天窗口用例把一个合成 JSON 回复分成两段，看到第一字后才送出其余字段。时间从测试提交用户输入起算，分别记录到首字实际出现在聊天窗口、静音语音替身收到朗读请求的时刻。观察值包含窗口渲染和测试调度。

- `ChatWindowLifecycleTest` 检查首字显示、完整提交后朗读、停止后丢弃旧回调、关窗回到空闲和新对话清除前文。
- `PetPointerWindowTest` 与 `PetRoamingWindowTest` 检查拖放、转身、行走让位给通讯与睡眠。
- `FishAudioClientTest` 使用回环替身和同一缓存目录，新客户端能复用已经生成的固定台词音频。
- `verify_startup.py` 检查独立检出的实际桌宠窗口与模型启动。语音测试使用合成音频和静音替身，实际 Fish 音色和首声时延待试听。

复现聊天窗口观测的命令如下，其他两个窗口用例分别使用 `closure.nativeTransitionTest` 和 `closure.nativeRoamingTest` 开关。

```sh
./mvnw -B -Djava.awt.headless=false -Dclosure.nativeChatTest=true -Dtest=ChatWindowLifecycleTest test
```
