# Closure 动作调整：本地验证

本次调整沿用已接入的新角色卡和多轮会话，继续只在本地验证。源码提交不推送，不创建 PR、不运行远端 CI、不合并。

## 对话中的持续姿态

双击人物或打开“通讯”后，人物保持原资源 `Sit` 上的思考姿态。等待输入、回复完成、出错、停止或新建对话，都不会使它站回普通待机。朗读时在同一坐姿上叠加口型，结束后回到思考；调侃、开心等反馈不会把坐姿替换成站立互动。

关闭或隐藏对话框才退出这个持续姿态。再次打开时重新进入，窗口重建仍保留现有进程内聊天记录。

## 行走入口

资源确实包含 8 秒的 `Move` 片段。此前只出现在离线导出中，没有绑定到应用动作。现在可以右键人物，选择“动作 → 行走”，在当前位置循环播放原有片段。点击或拖动人物、选择其他动作，或打开通讯都会结束行走。

通讯窗口显示期间，“行走”入口不可用，以保持用户要求的持续思考姿态。该动作不自动移动桌面窗口，拖动位置仍由用户控制。

## 长待机与唤醒

未与桌宠交互满 2 分钟后，普通待机自动变为 `Sleep`。点击、拖动、选择动作或打开通讯会唤醒。关闭通讯后重新计时，避免刚关窗就睡着。

对话框显示或请求、朗读仍在进行时，不会被待机计时强制打断。长待机期间如有必要的提醒语音，播放结束后恢复睡姿；睡着时不再主动触发闲聊。这里计算的是与桌宠的交互间隔，不监控全局键盘、鼠标或其他应用。

## 检查顺序

1. 打开通讯，不发送消息，确认人物持续保持思考坐姿。
2. 连续聊天并触发朗读，确认身体保持坐姿，朗读结束仍回到思考。
3. 点“停止”和“新对话”，确认姿态不受请求结束影响；关闭通讯后退出思考。
4. 右键“动作 → 行走”，观察原有移动循环；再点击或拖动唤醒并停止行走。
5. 关闭通讯，静置约 2 分钟，确认进入睡姿；点击人物后唤醒。

本次离线检查使用假模型、静音语音替身和可控时钟验证窗口与动作时序，另检查实际 Spine 像素和循环帧。它们不替代用户目视或听音验收。Spine 骨架、图集、贴图、声模、适配器和私有配置均未调整。

安装会重启本地桌宠。现有聊天记录只在进程内保留，重启会清空。原启动入口保持不变；精确文件备份与本地安装记录位于本次工作副本的 `.ai-workflow/motion-local/`。
