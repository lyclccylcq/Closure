# Closure 文本与语音质量回退修复

本次按用户反馈修复公式化安慰/劝告与一条回复内的声线漂移，继续只在本地验证，不推送、创建 PR 或合并。文字模型、推理参数、语音后端、LoRA、原参考录音和私有配置均不更换。

## 文本

此前的精简角色卡删减了熟悉的同伴关系、短而具体的日常接话，以及求助时先给具体判断等规则，保留了较多事实与操作限制。它可能把普通闲聊推向谨慎、客套的通用助手表达。此次恢复这些对话规则，关心按语境出现，不把普通分享自动改成安慰或劝告；没有加入固定回答示范，也没有只针对某几个词做屏蔽。

多轮历史继续保留，但助手只发送可见正文一次。原始回复对象仍留作界面和诊断数据，朗读摘要、情绪标签不会重复注入下一轮。仍使用最近完整轮次、24,000 码点预算和进程内会话；取消或失败不会写成成功历史。

## 语音

Java 端原本已每条回复选一次 profile，但 Qwen 服务仍逐句独立运行完整 ICL，再把音频拼接。这是可证实的生成边界问题；其对主观声线的具体影响还需试听。

本次把普通回复的最多 120 字作为一次连续生成，不因句号或问号分成多个模型调用。若返回结果触及原有 768 token 上限，会明确报错，不把可能截断的音频算成成功。超过 120 字的辅助长文本仍分块以限制单次生成长度，不能据此保证任意长音频完全无漂移。

本地 Qwen 统一采用原有 neutral 参考作为说话人锚点，不随 QUESTION/TEASING 切换参考录音。情绪标签仍供显示和动作使用；语音先优先保持同一人、连贯的说话方式。原 GPT-SoVITS 路径仍保留其原来的情绪 profile 选择。本次不声称 Qwen 已达到此前 GPT-SoVITS 的音质。

## 本地检查与试听

工程检查使用假模型、回环接口、可控生成器和静音语音替身验证调用次数、文本完整性、单一参考与窗口生命周期。必要时通过现有本机 Qwen 服务，用同一段合成测试文字生成修复前后语音供用户试听；不读取原参考样本或模型权重、不调用云端额度。服务未运行时不伪造对照。

试听应重点检查同一句话中是否突然换声线、句间是否机械转调、整段是否仍像同一个人在说话。文本应使用相同类型的日常分享、故障求助和连续追问观察是否恢复具体反应。结构测试不能替代真实模型表现或听音验收，结果记录于 `.ai-workflow/reply-quality-local/`。

替换需要重启桌宠，进程内的临时对话随重启清空。原启动入口保持不变，具体受影响文件有精确备份，其他模型/动作与私有设置保持原状。
